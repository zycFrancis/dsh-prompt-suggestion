# Roadmap

本文件是 [dsh-prompt-suggestion](https://github.com/zycFrancis/dsh-prompt-suggestion) 的长期维护计划。**优先级不预先拍板**:各项以 GitHub 用户反馈(issue / discussion / 采纳数据)为主要输入动态调整,内部构想仅作候选池。

状态标记:`💡 候选`(未排期) · `🚧 进行中` · `✅ 已发布` · `🧊 搁置` · `❌ 放弃`

---

## 一、体验增强

| 状态 | 方向 | 说明 | 反馈驱动信号 |
|---|---|---|---|
| 💡 候选 | **多候选轮换** | 生成 2-3 条建议,Tab 采纳、Shift+Tab 或连续 Tab 循环切换 | "想选别的"类反馈 |
| 💡 候选 | **手动触发** | `/suggest` 命令或输入栏角标按钮,主动要一条建议(Esc 关掉后反悔场景) | "误关/等不及"类反馈 |
| 💡 候选 | **会话级开关** | 命令或 UI toggle 临时关闭单个会话的建议,不动全局 `enabled` | "某些会话不想要"反馈 |
| 💡 候选 | **采纳反馈闭环** | 记录采纳/忽略/编辑后采纳比例,做质量观测与提示词调优依据 | 自驱,亦可回应"建议质量"类 issue |

## 二、建议质量

| 状态 | 方向 | 说明 | 反馈驱动信号 |
|---|---|---|---|
| 💡 候选 | **工具回合上下文** | 收集 `tool/result` 摘要(控制 token),让工具密集回合的建议含关键信息 | "工具回合建议不贴切"反馈 |
| 💡 候选 | **空输出学习** | 同模型同档位连续 N 次空输出时,本会话内记住并直接走降档链第一档 | 自驱(省无效请求) |
| 💡 候选 | **建议去重** | 连续回合相同建议时轮换或降权 | "重复建议"反馈 |

## 三、宿主演进跟随(被动维护)

不排期,但每次 DSH 升级后执行例行检查:跑 `node --test` + 开 `debugLog` 抽查一轮。

| 依赖锚点 | 风险表现 | 现有防线 |
|---|---|---|
| typert 清单文法(历史:0.1.0-rc.8 要 `schema` 字段,0.2.0-rc.2 要 `create` 工厂) | 插件注册静默失败 | `test/typert.mjs` 直接调宿主校验器 |
| composer DOM 锚点(`data-input-scroll` / `data-composer-placeholder` / `:has()`) | 建议不显示或错位 | 只读测量,宿主结构变化不影响其余功能 |
| `llm/stream` chunk 协议(`text-delta`/`reasoning-delta`) | 聚合静默失效、建议恒空 | 单测 mock 即协议快照,测试失败=协议变了 |
| slots standardProps(`useInput`/`inputActions`) | 组件静默不渲染 | 已有防御检查,降级安全 |

## 四、工程与分发

| 状态 | 方向 | 说明 |
|---|---|---|
| 💡 候选 | **e2e 脚本化** | 把"起 Web 实例 → session/create → prompt → 轮询 get"固化为 `test/e2e.mjs`,发版前一键回归 |
| 💡 候选 | **发布流程脚本** | 版本号+CHANGELOG+tag+release 四步固化为 `scripts/release.sh` |
| 💡 候选 | **npm 发布** | 发 npm 后 `dsh plugin add dsh-prompt-suggestion` 免 `github:` 前缀,提升市场可见度(dshhub 元数据已就位) |
| 💡 候选 | **成本透明** | 建议请求的 token 消耗统计与展示,回应额度敏感用户 |

---

## 反馈如何改变本文件

1. GitHub issue / discussion 中出现的功能诉求,计入对应条目的"反馈驱动信号"列(记录 issue 链接)
2. 同类诉求 ≥3 个独立用户 → 升为近期项并进入实现
3. 决定不做/暂缓的条目改 `🧊 搁置` 或 `❌ 放弃`并注明原因,不删除(保留决策历史)
4. 已实现条目改 `✅ 已发布` 并链接对应 release
